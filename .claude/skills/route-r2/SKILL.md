# Route R2 — Rust-first, prove the gap directly

Pure composition; every procedure lives in the stage skill named. Invocation
resolves the target definition. What makes this route R2: candidates are Rust
diffs, and the verification carries no `opt_eq_spec` — the campaign's
effort numbers on this route are the price of skipping the Lean lemma
layer, which is exactly the bake-off's question.

## Invocation

**Human invocation:** start with `/route-r2` alone. Ask: **“Which CompPoly
operation should route R2 optimize and verify?”** Resolve and confirm that
single target, then run this supplied composition; its Rust-first candidate
stage is not a separate user parameter. A different composition is a distinct
named route skill.

**Agent invocation:** bypass the dialogue with:

```yaml
agent_request:
  target: CompPoly.<fully-qualified-definition>
```

Return an invalid or missing target to the invoking agent, never to the human.

1. `compoly-analyze` — target definition in → optimization brief out (its
   cost model reads on the Rust hot path).
2. `perf-loop`, candidate stage `rust-direct` — brief in → bench-steered
   accepts as in the default loop, except: candidates arrive as Rust (the
   translation step is skipped) and their pre-bench contract is
   `rust-direct`'s ceiling audit instead of the opt-contract. Out: staged
   champion, candidate ledger rows, `champion/<op>` branch material.
3. `verify-campaign` (K=1, trigger `champion-accept`) — champion branch in →
   verified module, campaign ledger row, merge plan out; specs relate the
   extracted model directly to the original CompPoly definition, with
   `aeneas-equivalence-bridges` consulted before any relation is invented
   if the champion moved the representation.
